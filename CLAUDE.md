# Smart Furniture — Development Reference

## ⚠️ WORKING AGREEMENT — READ FIRST (non-negotiable)

This is a **paid Prestige theme** ($400, licensed). The merchant owns its defaults and its
live content. This branch (`claude/figma-connection-*`) **will be published as the live theme**,
so every file here is production-facing.

### Never edit these files unless changing them IS the explicit, stated goal:

- `config/settings_data.json` — live merchant theme settings & color schemes
- `config/settings_schema.json` — theme settings definitions
- `sections/*-group.json` (`header-group.json`, `footer-group.json`, `overlay-group.json`) — live section-group content
- `templates/**/*.json` — live page content/layout the merchant configures in the theme editor

These JSON files hold **live merchant content**. They are the #1 source of merge conflicts
and accidental content wipes in the Shopify GitHub integration. Leave them alone. If a task
genuinely requires a JSON change, call it out explicitly and confirm before touching it.

### Do your work in code, not content:

- Styling → `assets/theme.css` or scoped `{% stylesheet %}` blocks
- Behavior → `assets/theme.js` (respect the importmap + custom-element guard pattern)
- Markup/logic → `.liquid` section/snippet/block files
- Copy → `locales/*.json` (locale files are code-side, safe to edit)

### Process rules (these were violated before — do not repeat):

1. **Verify end-to-end before claiming done.** Before saying a feature works, confirm every
   referenced section type, setting id, and block type actually exists in that section's
   `{% schema %}`. Use the Shopify Liquid skill / MCP to validate — do not assume.
2. **Prefer native Prestige sections & settings** over custom code. Only write custom code
   when Prestige has no native equivalent, and keep it minimal.
3. **No large custom codebases.** Maintain mobile + web responsiveness and fast load times.
4. **When in doubt, ask** — do not guess at merchant intent or theme internals.

## Shopify Theme Architecture

### Directory Structure

```
layout/          → theme.liquid (single layout, importmap for JS modules)
templates/       → JSON templates (index, product, collection, cart, page, customers/*)
sections/        → 50+ section files (.liquid) + 3 group JSONs (header, footer, overlay)
snippets/        → 55+ reusable partials (product-card, button, input, icon, etc.)
blocks/          → 11 block files (accordion, button, heading, image, rich-text, video, etc.)
config/          → settings_schema.json (theme editor config) + settings_data.json (active values)
assets/          → theme.css, theme.js (6256 lines, 80+ web components), vendor.min.js, photoswipe
locales/         → 25+ language files, en.default.json is canonical
```

### JS Architecture

- **Module loading**: ES importmap in theme.liquid registers `vendor`, `theme`, `photoswipe`
- **Custom elements**: 80+ web components, all registered with guard pattern: `if (!window.customElements.get("name")) { window.customElements.define("name", Class); }`
- **Class hierarchy**: `HTMLElement` → `EffectCarousel` / `ScrollCarousel` / `DialogElement` → `Modal` → `Drawer`
- **Events**: DOM CustomEvents, no centralized bus. Global events dispatch on `document.documentElement`, local on `this`
- **Key events**: `cart:refresh`, `line-item:change`, `carousel:select/change/settle`, `theme:loading:start/end`
- **Settings access**: Always via `window.themeVariables` (settings, strings, mediaQueries)
- **Utilities**: `cachedFetch()`, `throttle()`, `debounce()`, `waitForEvent()`, `matchesMediaQuery()`, `generateSrcset()`

### CSS Architecture

- **Single file**: `assets/theme.css` loaded with preload
- **CSS variables**: Generated by `snippets/css-variables.liquid` from theme settings on `:root`
- **Color schemes**: 5 schemes via `color_scheme_group`, applied as `.color-scheme--{id}` classes
- **Typography**: Fluid sizing with `clamp()`, variables `--text-h1` through `--text-h6`, `--text-xs` through `--text-xl`
- **Layout utilities** (Tailwind-like): `v-stack`, `h-stack`, `gap-{n}`, `container--{size}`, `section-spacing`
- **Responsive breakpoints**: `700px` (sm/tablet), `1000px` (md/desktop), `1150px` (wide), `1400px` (extra-wide)
- **Visibility**: `sm-max:hidden`, `md-max:hidden`, `md:hidden`, `sm:hidden`, `lg:hidden`
- **Section scoping**: All `<style>` blocks use `#shopify-section-{{ section.id }}`

### Section Conventions

1. Schema always starts with `color_scheme` setting (type `color_scheme`, default `scheme-1` or `scheme-2`)
2. Set `"class": "shopify-section--your-section-name"` in schema
3. Wrap content: `<div class="section-spacing color-scheme color-scheme--{{ id }}">` → `<div class="container">`
4. Use `{{ block.shopify_attributes }}` on all block wrappers
5. All schema labels use `t:` translation keys
6. Always include `{"type": "@app"}` in blocks for third-party integration
7. Delegate to snippets (`button`, `icon`, `section-header`, `surface`) — never duplicate markup
8. Use `bordered-section` class when `separate_section_with_border` is enabled

### Snippet Conventions

- **product-card.liquid**: Accepts `product`, `stacked`, `reveal`, `show_badges/rating/vendor/quick_buy` bools
- **button.liquid**: Accepts `content`, `href`, `size`, `style` (solid/outline/link), `stretch`, renders `<a>` or `<button>`
- **input.liquid**: Floating label pattern, `.form-control` → `.input`/`.textarea` + `.floating-label`
- **surface.liquid**: Inline CSS var generator for `--background`, `--text-color`, `--border-color`
- **icon.liquid**: Inline SVGs, stroke width from `settings.icon_stroke_width`

### Color System

Never hardcode colors. Use:
- `.color-scheme--{id}` classes with CSS variables `--accent`, `--text-color`, `--background`, `--border-color`
- Button colors: `--button-background`, `--button-text-color`, `--button-outline-color`
- Text modifiers: `.text-subdued`, `.text-on-sale`, `.link-faded`
- Surface snippet for manual overrides

### Responsive Images

```liquid
{{ image | image_url: width: image.width | image_tag: sizes: sizes, widths: widths, loading: 'lazy' }}
```
First visible image: `loading: nil, fetchpriority: 'high'`. All others: `loading: 'lazy'`.

## Development Rules

### When Creating New Sections

```liquid
{%- assign color_scheme_hash = section.settings.color_scheme.settings.background_gradient
    | default: section.settings.color_scheme.settings.background | md5 -%}

<div class="section-spacing {% if section.settings.separate_section_with_border %}bordered-section{% endif %}">
  <div class="color-scheme color-scheme--{{ section.settings.color_scheme.id }} color-scheme--bg-{{ color_scheme_hash }}">
    <div class="container">
      {%- comment -%} Section content here {%- endcomment -%}
    </div>
  </div>
</div>

{% schema %}
{
  "name": "t:sections.your_section.name",
  "class": "shopify-section--your-section",
  "tag": "section",
  "settings": [
    {
      "type": "color_scheme",
      "id": "color_scheme",
      "label": "t:global.colors.scheme",
      "default": "scheme-1"
    }
  ],
  "blocks": [
    { "type": "@app" }
  ]
}
{% endschema %}
```

### When Adding New JS Components

1. Register in the importmap in `layout/theme.liquid` if it's a new module
2. Use the custom element guard pattern
3. Dispatch events on `this` for local, `document.documentElement` for global
4. Access settings only via `window.themeVariables`
5. Keep minified JS under 16 KB per file — Shopify auto-minifies on request
6. Never use jQuery, React, Angular, Vue — use native browser APIs only
7. Always `defer` or `async` script tags — never parser-block rendering
8. Wrap variables in IIFE or module scope — no global namespace pollution
9. Use import-on-interaction for non-critical components

### When Modifying Styles

1. Never hardcode colors — use color scheme variables
2. Use existing utility classes (`v-stack`, `h-stack`, `gap-{n}`, `container--{size}`)
3. Scope custom CSS with `#shopify-section-{{ section.id }}`
4. Use the theme's breakpoints (700px, 1000px, 1150px, 1400px)
5. Typography: reference `--text-h1` through `--text-h6` and `--text-xs` through `--text-xl`
6. Ensure each CSS file's classes are used only within that file's render tree (enables Shopify auto-subsetting)
7. Never add external stylesheets — keep all CSS in `assets/theme.css` or section `{% stylesheet %}` tags

### Shopify Performance Rules (from shopify.dev)

1. **Images**: Always use `image_url` + `image_tag` filters — never hardcode img src
2. **Lazy loading**: `loading: 'lazy'` for below-fold images; omit loading + `fetchpriority: 'high'` for first visible
3. **Responsive**: Always provide `sizes` and `widths` attributes on `image_tag`
4. **Preload**: Max 2 resource hints per template via `preload_tag` or `preload` keyword
5. **Fonts**: Prefer system fonts; use `font_face` filter with `font_display: 'fallback'`
6. **Liquid perf**: Do complex operations (sort, assign) outside loops, not inside
7. **Render tag**: Always use `{% render %}` not `{% include %}` — render has proper scoping
8. **Section limits**: Max 25 sections per JSON template, max 50 blocks per section
9. **Lighthouse target**: Minimum 60 average across home, product, collection pages

### Accessibility Rules (from shopify.dev)

1. Valid semantic HTML — headings in order (h1→h6), `nav` for navigation, `button` for actions, `a` for links
2. All `img` elements need `alt` attributes — descriptive for content, empty `alt=""` for decorative
3. All form fields need labels — `for`, `aria-label`, or floating label pattern
4. Color contrast: 4.5:1 for small text, 3:1 for large text and icons
5. Min 44×44px touch targets for primary controls
6. Support Tab/Shift+Tab, Enter/Space, Esc for keyboard navigation
7. Use `aria-expanded`, `aria-controls`, `aria-live` for dynamic UI state
8. Never use `autofocus` or positive `tabindex` values
